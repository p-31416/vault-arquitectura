## 1. Conceptos mínimos antes de tocar nada

Esto es lo único que necesitás saber para no perderte. El resto lo aprendés haciendo.

### ¿Qué es ComfyUI?

Un motor de generación de imágenes (y video) con IA. A diferencia de otras herramientas, **NO tiene una pantalla con botones**. Es una **mesa de trabajo con cajones (nodos)** que vos conectás con cables para armar un "flujo de trabajo" (workflow). Cada nodo hace una cosa: cargar un modelo, escribir un prompt, generar la imagen, guardarla.

**Analogía arquitectónica:** es como armar un plano de instalaciones con bloques y conexiones. Cada bloque es un nodo, cada cable es un dato que viaja.

### ¿Qué es un workflow?

Un archivo `.json` que describe los nodos y cómo están conectados. Se puede:
- **Cargar** arrastrándolo a la ventana de ComfyUI.
- **Guardar** desde la UI (botón "Save").
- **Editar** a mano si sabés JSON, o visualmente moviendo nodos.

### Conceptos clave que vas a ver

| Término | Qué significa |
|---|---|
| **Checkpoint** | El modelo de IA propiamente dicho (ej: ArchitectureRealmix). Es el "cerebro" que genera la imagen. |
| **LoRA** | Un "ajuste fino" de un checkpoint. Pesa poco (~100 MB) y agrega un estilo. |
| **Prompt** | Texto que describe qué querés. Ej: "modern concrete building, sunset, photorealistic" |
| **Negative prompt** | Lo que NO querés. Ej: "blurry, low quality, distorted" |
| **Sampler** | El algoritmo que genera la imagen paso a paso. Ej: `euler`, `dpmpp_2m`. |
| **Scheduler** | Cómo se distribuyen los pasos. Ej: `karras`, `normal`. |
| **Steps** | Cuántos pasos de refinamiento. Más = más detalle, pero más lento. Default 20-30. |
| **CFG** (Classifier-Free Guidance) | Cuánto "obedece" al prompt. Bajo (3-5) = más libre/realista. Alto (7-10) = más literal al prompt. |
| **Seed** | El número aleatorio que determina la imagen exacta. Si ponés el mismo seed, sale la misma imagen. Sirve para iterar. |
| **Denoise** | Cuánto cambia la imagen original. 0 = idéntica. 1 = ignora original. Para img2img va de 0.3 a 0.8. |
| **ControlNet** | Una red neuronal que CONDICIONA la generación con una imagen extra (mapa de bordes, profundidad, etc.). Mantiene la forma, vos ponés el estilo. |
| **VAE** | Traductor entre el "espacio interno" del modelo y la imagen visible. Generalmente ya viene en el checkpoint. |
| **KSampler** | El nodo central que ejecuta la generación. Tiene todos los parámetros (steps, cfg, sampler, scheduler, seed, denoise). |

### ¿Qué hace cada carpeta dentro de `ComfyUI/models/`?

```
ComfyUI/models/
├── checkpoints/      → modelos principales (ArchitectureRealmix, Juggernaut XL)
├── loras/            → LoRAs (ajustes finos)
├── vae/              → VAEs separados (raro necesitarlos, suelen venir en el checkpoint)
├── controlnet/       → modelos ControlNet (canny, depth, scribble)
├── upscale_models/   → modelos de upscale (4x_foolhardy_Remacri)
├── clip/             → text encoders (CLIP-L, CLIP-G, T5)
├── clip_vision/      → para IP-Adapter (lectura de imagen)
├── ipadapter/        → modelos IP-Adapter
└── unet/             → modelos GGUF (alternativa a checkpoints, más livianos)
```

## 5. Bloque 2 — img2img croquis (60 min, esta noche)

**Objetivo:** tomar un croquis (foto de papel) y transformarlo en render.

**Diferencia con txt2img:** img2img **respeta la composición** de la imagen de entrada. El `denoise` decide cuánto cambia:
- `0.3` = retoque leve (mismo render, otro material)
- `0.5-0.6` = cambio de estilo manteniendo forma
- `0.8` = reinvención, mantiene solo los bordes principales

### 5.1. Conseguir el croquis

Sacale una **foto a un croquis en papel A4** con el celu. Tips:
- Luz pareja, sin sombras
- Croquis sobre una mesa blanca o superficie lisa
- Cuadrada o rectangular, ocupa la mayor parte del frame
- Guardala en `n_02-img2img/log-WF-croquis/00-inputs/01-croquis.jpg`

Si no tenés croquis a mano, podés usar cualquier imagen (foto de una casa, un render viejo) — el flujo es el mismo.

### 5.2. Cargar el workflow YA ARMADO

Andá a `n_02-img2img/log-WF-croquis/workflow_croquis_a_render.json` (o el `.json` que haya en esa carpeta), arrastralo a ComfyUI.

El workflow tiene un nodo extra comparado con txt2img: `LoadImage` (para tu croquis) y un `ImageScale` antes del sampler.

### 5.3. Conectar tu croquis

Click en el nodo `LoadImage` → "choose file" → navegá a tu `01-croquis.jpg`.

### 5.4. Ajustar parámetros

- `KSampler.denoise`: empezá con **0.6** (buen balance para croquis → render)
- Si el render sale "demasiado parecido al croquis" (manchón de líneas): subí a 0.75
- Si sale "ya no parece tu edificio": bajá a 0.45
- Mismo prompt arquitectura del Bloque 1
- **Regla obligatoria** (de `reglas-workflows-comfy.md`): el `ImageScale` debe estar a 512x512 antes del KSampler

### 5.5. Correr 3 variantes (cambiando denoise)

- Corrida 1: `denoise 0.45` → guarda como `n_02-F-01.png`
- Corrida 2: `denoise 0.6` → guarda como `n_02-F-02.png`
- Corrida 3: `denoise 0.75` → guarda como `n_02-F-03.png`

### 5.6. Anotar en el log

Editá `n_02-img2img/log-WF-croquis/02-WF-log.md` con las 3 corridas y qué denoise ganaste.

### 5.7. Pasar / No pasar

**Pasar si:** la composición de tu croquis (dónde están las paredes, las ventanas) se respeta y aparece un render con material reconocible.

**Si no pasa:**
- Canny no está respetando: probablemente necesites un preprocesador (eso es el Bloque 3)

## 8. Bloque 5 — Rhino 2 img (90 min, mañana 12:30) 🦏

**Objetivo:** tomar un modelo 3D de Rhino y transformarlo en render arquitectónico, **sin depender del MCP** (que no existe nativo).

**Por qué este es el bloque más importante:** es el que te falló antes. La solución per la investigación `2026-10-08`: **render passes de Rhino → ComfyUI img2img + ControlNet**.

### 8.1. Preparar el modelo en Rhino (15 min)

1. Abrí Rhino con **cualquier modelo 3D simple** (cubo, casa básica, o un proyecto del estudio).
2. Configurá **3 viewports** del mismo encuadre:
   - **Viewport A — Shaded/Rendered:** `Render` mode → export PNG 1024×1024 → `01-shaded.png`
   - **Viewport B — Technical/Lineart:** `Technical` mode → export PNG → `02-lineart.png`
   - **Viewport C — Depth:** `Ghosted` mode (suficiente para probar) → export PNG → `03-depth.png`
3. Guardá los 3 PNG en `n_05-rhino-mcp/00-inputs/`

**Si no tenés modelo a mano:** en Rhino → `Box` 10×10×10 + `Mesh sphere` r=5 → `Render Preview` → exportá los 3 passes.

**Por qué 3 passes:**
- Shaded → la **base** de la que img2img parte (VAEEncode)
- Lineart → ControlNet Canny (las **líneas exactas** de tu modelo)
- Depth → ControlNet Depth (la **profundidad/volumen**)

### 8.2. Cargar el workflow base de ControlNet (Bloque 3) (10 min)

Andá a `n_03-controlnet/n_03-WF01-croquis-estadio/`, arrastrá el `.json`.

### 8.3. Adaptar el workflow a Rhino passes (45 min)

1. Reemplazá el `LoadImage` único del croquis por **3 LoadImage** (uno por pass):
   - `LoadImage` A: `01-shaded.png` → **VAEEncode** → entrada del KSampler
   - `LoadImage` B: `02-lineart.png` → **ImageScale 512** → **Canny (30/100)** → **ControlNetLoader canny** → **ControlNetApplyAdvanced** (strength 0.7, end 0.8) → entrada al KSampler
   - `LoadImage` C: `03-depth.png` → **ImageScale 512** → **Depth (dpt_hybrid o MiDaS)** → **ControlNetLoader depth** → **ControlNetApplyAdvanced** (strength 0.85, end 0.85) → entrada al KSampler
2. En el KSampler: `denoise 0.5` (entre 0.45 y 0.55 — "render rescue": mantiene la geometría pero le pone piel nueva)
3. **Checkpoint:** `architecturerealmix_v11.safetensors` (SD1.5, entra todo en 8GB)
4. Prompt arquitectura: el del Bloque 1 (modern concrete, minimalist, etc.)
5. Guardá el workflow como `n_05-rhino-mcp/00-WF-rhino-2-img.json`

### 8.4. 3 corridas (15 min)

3 seeds distintas, guardar como `n_05-F-{01,02,03}.png`.

### 8.5. Evaluar (5 min)

**Pasar si:**
- La **composición y proporciones** del modelo original se preservan (las paredes están donde estaban)
- Aparecen **materiales fotorrealistas** (concreto, vidrio) en lugar de los colores planos del shaded
- La **profundidad** se siente coherente (no hay paredes "flotando" o volúmenes mal resueltos)

**Si no pasa:**
- Demasiado parecido al shaded de Rhino: bajá `denoise` a 0.4
- Demasiado reinventado: subí `denoise` a 0.6
- Canny no respeta: subí `strength` Canny a 0.85
- Depth confunde: bajá `strength` Depth a 0.7
- Líneas con doble borde: ajustá Canny thresholds (probá 50/150)

**Si Funciona:** este es el workaround del MCP. Documentalo en `n_05-rhino-mcp/README.md` con los parámetros exactos y 1-2 renders de muestra. **El MCP sigue sin existir nativo** — pero ya no lo necesitás para este flujo.

**Si no funciona:** anotá los gaps en el log, y dejá `n_05-rhino-mcp/README.md` con los hallazgos. Próximo ciclo: probar `comfyui-3d-viewport-pro` o armar un script RhinoPython que automatice el export de passes.

**Checkpoint S5:** 3 renders Rhino 2 img. Workflow documentado en `n_05-rhino-mcp/00-WF-rhino-2-img.json`. Caso resuelto o con gaps explícitos.

## 12. Troubleshooting exprés (si algo se rompe)

| Síntoma | Causa probable | Fix |
|---|---|---|
| OOM en SDXL | res/batch/CN de más | `--lowvram --cpu-vae`, res ≤1216x832, 1 CN, batch 1 |
| Negro / artefactos | scheduler/cfg de DiT mal | GGUF: cfg 1.0, steps 4-8, scheduler simple |
| Canny no guía | strength/end bajos o res ≠512 | strength ≥0.8, end 0.8, ImageScale lanczos 512 |
| Modelo no aparece | carpeta equivocada | `models/checkpoints|controlnet|upscale_models`, Refresh, reiniciar |
| Cola atascada / VRAM full | modelo anterior en memoria | `Free VRAM` (Manager) / reiniciar |
| ComfyUI no abre | puerto 8188 ocupado | cambiá el puerto en `corre_comfyui.bat`: `--port 8189` |
| Python no encontrado | env conda no activo | usá path completo: `P:\Anaconda\envs\comfyenv\python.exe` |
| MCP no conecta a ComfyUI | ComfyUI no corre o puerto mal | `Test-NetConnection 127.0.0.1 -Port 8188` desde PowerShell |

Más detalle en `wiki/glosario/interno/pbooks/pbk-comfyui.md § Troubleshooting exprés` y `wiki/glosario/interno/pbooks/pbk-troubleshooting-reconexion.md`.

## 13. Glosario de términos (cheat sheet para imprimir)

| Término | Definición corta |
|---|---|
| **Checkpoint** | El modelo de IA (cerebro) que genera la imagen |
| **LoRA** | Mini-ajuste de un checkpoint (estilo, personaje) |
| **Prompt** | Texto que describe lo que querés |
| **Negative prompt** | Lo que NO querés |
| **Sampler** | Algoritmo de generación (euler, dpmpp_2m) |
| **Scheduler** | Distribución de pasos (karras, normal) |
| **Steps** | Cuántos pasos de refinamiento |
| **CFG** | Cuánto obedece al prompt (3-10) |
| **Seed** | Número aleatorio que define la imagen |
| **Denoise** | Cuánto cambia la imagen de entrada (img2img) |
| **ControlNet** | Red que condiciona con imagen (bordes, profundidad) |
| **VAE** | Traductor espacio interno ↔ imagen |
| **KSampler** | El nodo central de generación |
| **Strength (CN)** | Cuánto pesa el ControlNet (0-1) |
| **End % (CN)** | Hasta qué step se aplica el ControlNet |
| **VRAM** | Memoria de la GPU (vos tenés 8GB) |
| **DirectML** | Backend de cómputo en GPU AMD (vos usás este) |
| **CUDA** | Backend de NVIDIA (vos NO usás) |
| **GGUF** | Formato comprimido de modelos (cabe en menos VRAM) |
| **LoRA strength** | Cuánto pesa el LoRA (0.5-0.8 típico) |
| **Hires Fix** | Segundo pase que sube la resolución |
| **Upscaler** | Modelo que agranda la imagen sin perder calidad |
| **IP-Adapter** | Nodo que lee una imagen de referencia para estilo |
| **img2img** | Modo: imagen de entrada + prompt → render |
| **txt2img** | Modo: solo prompt → render |
| **t2v / i2v** | Text-to-video / image-to-video |
| **RunPod** | Cloud GPU alquilado por hora |
