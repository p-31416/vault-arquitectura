# Log n01 — Local (LOC)

> **`log`** es la bitácora del nivel. Registra fallos, iteraciones, bugs y correcciones durante el desarrollo.

## 2026-06-30 — Creación del nivel

### Fallos detectados
- **A-MURO**: se configuró inicialmente como DASHED → debía ser CONTINUOUS. Solo el arco de apertura lleva DASHED.
- **A-PUER → A-PTA-**: el nombre de layer propuesto no seguía el estándar. Se renombró.
- **Arco**: color 254,254,254 incorrecto → corregido a 251,251,251. Lineweight 0.00mm insuficiente → 0.05mm (acLnWt005).

### Iteraciones

| # | Cambio | Motivo |
|---|--------|--------|
| 1 | Layer A-MURO: DASHED → CONTINUOUS | El DASHED distorsiona la lectura del muro; debe ser solo para arcos de apertura |
| 2 | A-PUER → A-PTA- | Estandarizar nomenclatura de layers con el formato `A-PTA-` |
| 3 | Arco: RGB 254→251, lw 0.00→0.05 | El gris muy claro se pierde al plotear; 251 es el estándar del estudio para elementos secundarios |

### Decisiones técnicas
- Se usan dos líneas separadas (antes/después del vano) en vez de `break` porque es más predecible
- `doorLeafLen` = doorWidth - 0.06 (0.03 m de marco a cada lado)
- Hinge point = esquina interior del marco izquierdo, mirando hacia la abertura

### Iteración 1 — Fix error quit/exit abort
- **Problema**: `(command "._layer" ...)` antes de `(getpoint ...)` dejaba un comando activo.
- **Solución**: mover `vl-cmdf "._layer"` a después de todos los `getpoint/getreal`. Usar `vl-cmdf` en vez de `command` para layers + `*error*` handler que restaura variables si algo falla.
- **Backup**: `bak-lisp-muro_puerta.lsp` actualizado antes de modificar.

## Pivote: de MP (muro+puerta) a LOC (local completo)

### Motivación
La prueba del comando `MP` reveló que dibujar una línea abierta con offset no es la forma correcta de trabajar. En la práctica arquitectónica se dibuja **el espacio interior** (local cerrado) y los muros se generan concéntricamente. El comando `LOC` reemplaza a `MP`.

### Cambios
- **Comando**: `MP` → `LOC`
- **Input**: polilínea cerrada del espacio interior (no línea abierta A→B)
- **Muros**: offset concéntrico de la polilínea, no offset bidireccional de una línea
- **Estructura**: fases progresivas (A: uniforme, B: variable, C: puerta)

### Output de prueba anterior
- Captura guardada: `output-n_01.JPG` (comando MP original)
- Estado: el comando MP se descarta, se construye LOC desde cero

## Iteración 2 — Rediseño del flujo LOC

### Fecha
2026-06-30

### Problema detectado
El algoritmo calculado en LISP (calcular normales manualmente, generar líneas, fillet) intenta resolver todo en código en vez de usar comandos nativos de AutoCAD.

### Cambios en el algoritmo
| Antes | Ahora |
|-------|-------|
| Bucle `getpoint` capturando puntos manualmente | `_pline` interactiva con loop `cmdactive` |
| Calcular offset en LISP (punto a punto) | Comando nativo `_offset` de AutoCAD |
| Fillet R=0 manual entre líneas | El offset de polilínea cerrada ya limpia esquinas |

### Lección
AutoCAD tiene comandos maduros para geometría (`_pline`, `_offset`, `_fillet`). Usarlos directamente es más robusto que reimplementarlos en LISP. El LISP debe orquestar, no calcular.

## Iteración 4 — Fase B: vano con _break + conexión de puntas

### Fecha
2026-06-30

### Contexto
Fase A funcionando. El usuario ahora necesita poder cortar un vano de puerta en el muro. Se implementa dentro del mismo comando `LOC`, después del offset.

### Implementación
1. Después del offset, pregunta: "Agregar vano? [S/N] <S>:"
2. Usuario cliquea un punto en el muro
3. Usuario elige 80/90/100 → vano = medida + 6 cm
4. Para cada polilínea (interior y exterior):
   - `vlax-curve-getClosestPointTo` + `getDistAtPoint` → distancia al clic
   - Break points centrados: dist ± halfWidth (con wrapping si cruza el fin de curva)
   - `vlax-curve-getPointAtDist` → coordenadas
5. `_break _F` en ambas polilíneas
6. Re-obtener start/end de cada polilínea (ahora abiertas)
7. Conectar por proximidad con `_line`

### Decisiones técnicas
- **`_F` en break**: necesario para evitar ambigüedad al pasar ename como selección
- **Wrapping manual**: `vlax-curve-getPointAtDist` no wrappea automáticamente en curvas cerradas; se implementa suma/resta de `totalLen`
- **Longitud total separada**: inner y outer tienen sus propias `totalLen` porque el offset de 0.15 agranda la exterior
- **Conexión por proximidad**: se conectan las puntas más cercanas, que son las que corresponden al mismo lado del vano
- **A-PTA-**: el layer de puerta se crea pero no se usa aún (está reservado para Fase D)
